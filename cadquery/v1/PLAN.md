## Current CadQuery Parts Page

The parts page is implemented by:

- `cadquery/v1/ui/parts.html`
- `cadquery/v1/ui/src/parts.ts`
- `cadquery/v1/ui/src/parts.css`
- `cadquery/v1/ui/vite.config.ts`

`parts.ts` fetches `parts/index.json`, renders a Fusion-style tree, and shows
the selected part's generated PNG views plus any metadata supplied in the index:
origin, center of gravity, mass, density, volume, area, body count, materials,
bounds, and Fusion joints.

The index and images are generated by:

- `cadquery/v1/python/render_part_images.py`
- `rosie cadquery v1 parts-image`
- pixi task `parts-image` in `cadquery/v1/pixi.toml`

The current default parts list is still arm-centric:

```text

```

The current renderer groups only `base,L1,L2,L3,L4,L5` as `robot-arm`; every
other part lands in the generic `cell` group. The Full Cell catalog needs a
better grouping pass so the browser tree mirrors the Fusion subassemblies.

## Extraction Plan

1. Refresh and snapshot the live Fusion context.

   ```powershell
   .\rosie.ps1 autodesk v1 context-refresh --json
   .\rosie.ps1 autodesk v1 subassemblies --json
   ```

   Keep the refreshed `%ROSIE_HOME%\autodesk\fusion-context.json` as the source
   of occurrence paths, visibility, body counts, and bounding boxes for the first
   catalog manifest.

2. Export Fusion metadata for the selected subassembly list.

   ```powershell
   $parts = "Fireball-F5-TCG10254-G2:1,h-frame:1,base v2 (2):1,positioner gear:1,[OLD] h block assembly:1,H gear:1,table adapter:1,positioner-table:1,positioner-table:2,Base:1,L1:1,L2:1,L3:1,L4:1,L5:2"
   .\rosie.ps1 autodesk v1 export-parts-metadata `
     --root "Full Cell(simplified CAD):1" `
     --parts $parts `
     --out "$env:ROSIE_HOME\cadquery_steps\full_cell_simplified\parts_metadata.json" `
     --timeout 10m
   ```

3. Export one STEP per catalog entry.

   Preferred path: if the subassembly is backed by a standalone Fusion cloud
   data file, use `export-doc-step` into the safe `cad.step` location:

   ```powershell
   .\rosie.ps1 autodesk v1 export-doc-step `
     --project Gradient01 `
     --file-name "positioner-table" `
     --out "$env:ROSIE_HOME\cadquery_steps\full_cell_simplified\positioner_table_1\cad.step"
   ```

   Required gap to close: the current Autodesk CLI exports the whole active
   design to STEP (`export-step`) or component STLs (`export-component`), but it
   does not yet expose a clean "export this occurrence path as STEP" command.
   If `export-doc-step` cannot distinguish duplicated occurrences such as
   `positioner-table:1` and `positioner-table:2`, add a small Autodesk command
   like `export-occurrence-step --occurrence "<full path>" --out <cad.step>`
   using Fusion's export manager from the active assembly context.

4. Render the CadQuery parts catalog.

   ```powershell
   .\rosie.ps1 cadquery v1 parts-image `
     --source "$env:ROSIE_HOME\cadquery_steps\full_cell_simplified" `
     --metadata "$env:ROSIE_HOME\cadquery_steps\full_cell_simplified\parts_metadata.json" `
     --assembly "Full Cell (simplified CAD) (Z-up)" `
     --parts $parts `
     --theme both `
     --annotations basic `
     --live-ui `
     --force
   ```

   Use `--live-ui` for the running page on the build host so generated PNGs and
   `parts/index.json` update in the staged Vite source instead of dirtying the
   repo checkout.

5. Improve the parts tree before relying on the catalog for review.

   Update `render_part_images.py` so grouping can come from metadata rather than
   the hard-coded `robot-arm` vs `cell` split. The first grouping should be:

   - `Cell floor`: `Fireball-F5-TCG10254-G2:1`
   - `H-frame`: `h-frame:1`, `base v2 (2):1`, `positioner gear:1`,
     `[OLD] h block assembly:1`, `H gear:1`, `table adapter:1`
   - `Positioner tables`: `positioner-table:1`, `positioner-table:2`
   - `Rosie 1400 arm`: `Base:1`, `L1:1`, `L2:1`, `L3:1`, `L4:1`, `L5:2`

   This can be implemented as a small mapping keyed by exact part filter and
   later replaced by tree data derived from `full_path`.

6. Optional: add CadQuery library entries.

   The `/parts` page is the immediate target, but the main CadQuery UI reads a
   separate `ui/public/library/index.json` and per-item bundles containing
   `cadquery_manifest.json`, `robot.urdf`, and `meshes/*.stl`.

   For each subassembly that should also appear in the main library viewer:

   ```powershell
   .\rosie.ps1 cadquery v1 convert `
     --step "$env:ROSIE_HOME\cadquery_steps\full_cell_simplified\h_frame_1\cad.step" `
     --out cadquery/v1/ui/public/library/full_cell_h_frame `
     --split `
     --robot full_cell_h_frame
   ```

   Then append a matching item to `cadquery/v1/ui/public/library/index.json`.

7. Verify the live catalog.

   ```powershell
   Invoke-RestMethod http://<build-host>:5184/cadquery/v1/ui/parts/index.json
   Invoke-WebRequest -UseBasicParsing http://<build-host>:5184/cadquery/v1/ui/parts/Full_Cell_simplified_CAD_Z_up/positioner_table_1/dark/iso.png
   ```

   Check that:

   - `index.json` contains all expected parts.
   - Each part has `iso`, `front`, `side`, and `top` PNGs.
   - metadata rows show Fusion origins, body counts, mass properties, and joints
     where available.
   - the tree groups match the Full Cell subassembly structure.
   - duplicated parts such as `positioner-table:1` and `positioner-table:2` are
     distinct entries with distinct STEP paths and origins.
